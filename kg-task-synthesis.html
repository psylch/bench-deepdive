01Kimi K3 4.2.2

做法（原文）：建一张「自我演化、层级组织」的知识图谱，覆盖知识密集和编程领域。

  • 结构是 DAG，人只给粗种子节点，例如 CS/AI、生物医学、编程、数学、物理、化学、人文。
  • 每个节点交给一个 agent，先多轮联网搜索把概念查清，再加更细的子概念；加之前先在图里找相同或相近的节点复用；边永远从粗指向细；新节点再分给新 agent，直到 agent 判断概念「足够原子」。
  • 造题三步：按领域和题型比例在不同粒度采样关键词（可多个相关关键词一起抽）→ 关键词拼上祖先节点的上下文作为检索词，去网上取公开论文、博客、代码仓库 → 合成 agent 按指定题型（编程、知识、视觉等）出题。

未公开：节点数、层数、每类题量、合成题的校验方法。

下面每条都和这四个要素对照：图谱怎么建 / 怎么采样 / 素材从哪来 / 怎么验题。

02Simula（Google）

  • 全称：Reasoning-Driven Synthetic Data Generation and Evaluation
  • 机构 / 时间：Google、Google DeepMind、EPFL；TMLR 2026-03，arXiv 2026-03-31
  • 链接：arXiv 2603.29791

图谱怎么建：不需要种子数据。先由推理模型根据用户对数据集的描述，列出若干「变化因子」，每个因子按用户指定的深度，用广度优先展开成一棵分类树。树越深，覆盖控制越细。

怎么采样：在多棵树的叶子节点上组合采样，再生成数据；论文把多样性拆成「全局多样性」（树覆盖了多少）和「局部多样性」（同一组合下的变化）。

怎么验题：生成后用模型做批评和复核。论文的结论之一是不同数据集需要的东西不一样，有的更依赖质量控制，有的更依赖复杂度或局部多样性。

与 K3 的异同：同样是「先画覆盖地图、再按地图采样」。区别在于 Simula 的树来自模型推理，不联网取真实素材；K3 每个节点都由 agent 联网查证，素材也来自真实网页。

开源：社区复现 Mercity-AI/Simula，6⭐，最近更新 2026-09-10，README 自述「受 Simula 式流程启发」，不是 Google 官方代码。

03STEPS

  • 全称：Towards Compositional Generalization of LLMs via Skill Taxonomy Guided Data Synthesis
  • 机构 / 时间：北航、智源、北理工、中科院计算所；arXiv 2026-01
  • 链接：arXiv 2601.03676

图谱怎么建：先建技能共现图，再按「最小化结构熵」递归把内部连接紧密的技能归成组，得到一棵可解释的层级技能树。人不手画分类。

怎么采样：把出题当成约束下的信息最大化问题，挑选在树上「结构信息增益」最大、语义仍然连贯的技能组合。原文的意思是：只在一小块区域里组合技能是冗余的，跨区域组合才有新信息。

效果：在复杂指令遵循评测上，比 Instruct-SkillMix 高（36.3 vs 30.8），在下游 agent 评测上组合泛化也更好。

与 K3 的异同：K3 的树是「知识概念」，STEPS 的树是「技能」；两者都关心多个节点组合出题。STEPS 给了一个怎么挑组合的数学准则，K3 没写。

缺口：论文写的代码地址 github.com/STEPS 不是有效仓库。

04CLI-Universe

  • 机构 / 时间：南京大学、阶跃星辰、ZODA、上海 AI Lab、华中科大；arXiv 2026-06-22
  • 链接：arXiv 2606.22883

图谱怎么建：四维能力 taxonomy。领域由人策划，作为入口；另外三维各有预定义的取值池：

  • 技能类型：算法、系统、配置、密码学等
  • 能力：探索、错误恢复、约束满足、长程规划等
  • 工程形态：写新功能、调试、DevOps、重构等

怎么采样和取素材：在四维里抽组合作为锚点，围绕锚点头脑风暴任务，按创意、技术依据、可行性打分；高分候选再做「证据引导的 deep research」，去查仓库、文档、issue 讨论和用例，把抽象规格变成有真实工具和真实坑的任务蓝图。

怎么验题：蓝图实例化成 Docker 环境，经过 rubric 门控的测试构造、带提示过滤、严格的 fail-to-pass 检查；测试 agent 和解题 agent 独立验证。全流程淘汰约三分之二的候选。

效果：CLI-Universe-6K（6,000 条轨迹）微调 Qwen3-32B，Terminal-Bench 2.0 达 33.4%；去掉任何一个组件掉 3–6 个点。

与 K3 的异同：这是和 K3「采样 → 联网取真实素材 → 出题」最接近的一条，而且把 K3 没写的校验写全了。区别是它的 taxonomy 是人定的多维网格，不是 agent 长出来的树。

05Nemotron-Terminal

  • 全称：On Data Engineering for Scaling LLM Terminal Capabilities
  • 机构 / 时间：NVIDIA；arXiv 2026-02-24
  • 链接：arXiv 2602.21193；数据 HF nemotron-terminal

做法：提出 Terminal-Task-Gen，两路数据：一路把现有数据集（竞赛编程、数学、SWE）改写成终端任务；另一路用「原子技能 taxonomy」加多个领域（科学计算、软件工程、机器学习、安全、系统等）构造定向场景，可以控制难度、领域覆盖和原子技能。

效果：基于 Qwen3 训练，Terminal-Bench 2.0 上 8B 从 2.5% 到 13.0%，14B 从 4.0% 到 20.2%，32B 从 3.4% 到 27.4%。

未公开：taxonomy 的节点数和层数。

06LongCrafter

  • 机构 / 时间：中科院大学、中科院自动化所；arXiv 2026-07（v2 2026-08-03）
  • 链接：arXiv 2607.06160

做法：把长文本理解分成「局部 / 浅层」和「全局 / 深层」两级，细到 32 种任务类型，作为出题的全局先验；再按任务类型构造长上下文，拆成显式的证据图（跨段依赖），只依据定位到的证据片段出问答。

效果：在 Qwen2.5-7B 和 LLaMA-3.1-8B 上，LongBench、LongBench v2、LooGLE 超过所有 SFT 基线，也超过官方后训练模型，难题上提升最大。

与 K3 的异同：K3 4.1 节说过 1M 长上下文要拼「不读完全文做不出来」的合成任务；LongCrafter 是公开论文里把这件事拆成任务分类树 + 证据图的做法。

07BenchBench（评测侧）

  • 机构 / 时间：南洋理工；arXiv 2026-03-21
  • 链接：arXiv 2603.20807

做法：评的是「模型出题的能力」。三步：从种子 benchmark 抽结构化的「领域卡片」→ 让多个设计者模型按配额生成题集 → 多个答题模型组成评审组验证，能精确判分的用精确、数值、符号校验，否则用 rubric 评判。

规模：9 个变体（计算机、数学、医学、心智理论，含多语言多模态），生成 16.7K 题，过滤后约 15K，约 152K 条打分记录。

结论：出题能力和答题能力只中等相关（Spearman ρ≈0.37）；题目无效率和区分度负相关（Pearson r≈−0.62）。

开源：论文给的 github.com/koanatakiyo/BenchBench 目前打不开（404）。

09SearchArt（华为云）

  • 机构 / 时间：Huawei Cloud Post-Training Team；arXiv 2026-07（v2 2026-08-11）
  • 链接：arXiv 2607.24850

图谱怎么建：

  1. 选种子实体：按三个维度挑长尾实体，其中一条是「模型参数里见得少」。种子要同时兼顾知识新颖度、结构连通性和领域覆盖。对每个候选实体做多次随机游走，能稳定走到结构丰富子图的优先。
  2. 扩图：explorer agent 迭代地联网检索、抽取知识、建图、发现知识缺口，每轮生成的查询要超出当前图里已有的信息，比如相关实体、历史事件、组织关系、时间、地理和跨领域关系。
  3. 覆盖控制：种子实体挂在一棵「层级领域 taxonomy」下，预定义类别加上扩图过程中动态发现的新区域；各领域的采样配额实时调整，防止题目塌缩到少数热门话题。原文明确说，图采样天然会集中在连接稠密的领域，所以要用 taxonomy 拉平。

怎么采样和出题：批量采子图，按结构复杂度和证据分散度排序，留难子图作为出题上下文。

怎么验题：QA 一致性、轨迹质量、检索证据相关性三者联合校验。

规模与效果：DeepSearch QA 轨迹 20–149 轮，21.16% 在 80 轮以上；DeepResearch QA 覆盖 11 个领域，AI 与数据智能占 40.08%。Qwen3.5-27B 训练后：BrowseComp 70.06、BrowseComp-ZH 74.39、BrowseComp-Plus 63.49、WideSearch 64.0、DeepResearch-Bench 52.55。

与 K3 的异同：这是近一年里和 K3 思路最接近的公开工作：agent 主动扩图、用 taxonomy 管覆盖、用长尾概念对抗同质化。区别是 SearchArt 的节点是实体（人、机构、事件），K3 是概念（RoPE、GPU kernel）；SearchArt 只做搜索题，K3 覆盖多题型。

10Nemotron 3 Ultra 搜索数据

  • 机构 / 时间：NVIDIA；技术报告 2026-06-09
  • 链接：技术报告 PDF

做法（原文）：SFT 搜索数据沿用 Nemotron 3 Super 的轨迹，种子 prompt 基于 Wikidata：选连接多的枢纽实体，沿事实关系走 4–8 跳随机游走，构造多跳搜索题，用 Tavily 搜索求解，教师模型是 MiniMax 2.1。另外加了 OpenResearcher 的可商用子集（97K+ 条轨迹，离线浏览环境，1,500 万 FineWeb 文档的本地索引）。

与 K3 的异同：用现成知识图谱、按跳数控难度，是 2025 年 WebSailor / DeepDive 路线在大厂报告里的落地；没有 agent 扩图，也没有概念层级。

11GraphWalker

  • 机构 / 时间：中科院大学、中科院自动化所、清华；COLM 2026，arXiv 2026-03
  • 链接：arXiv 2603.28533；GitHub 35⭐，最近更新 2026-07-28

做法：在 KG 上做约束随机游走，合成 15k 条结构多样的轨迹（GraphSynth），先 SFT 建立探索先验；再用 6k 条专家轨迹（GraphRoll）教反思和纠错；最后用 EM 稀疏奖励做轻量 RL。

效果：CWQ、WebQSP 达 SOTA，CWQ 上比 GPT-4 驱动的 GoG 高 4.4% EM；在 GrailQA 和自建的 GraphWalkerBench（含训练里没见过的推理结构）上验证了泛化。

与 K3 的异同：图谱只是答题环境，不是素材索引；参考价值在于「先用图游走铺广度、再用少量专家数据补质量」的两段式。

12Graph2Eval

  • 机构 / 时间：浙大、蚂蚁集团等；CVPR 2026，arXiv 2025-10（v3 2026-03）
  • 链接：arXiv 2510.00507；GitHub 28⭐，最近更新 2026-01-10

做法：从多源外部数据建知识图谱当「任务空间」，用子图采样、任务模板和 meta-path 生成多模态文档理解和网页交互任务。

怎么验题：节点可达性分析、LLM 打分、相似度去重三级过滤。

效果：Graph2Eval-Bench 共 1,319 题；语义一致性平均提升 20%，可解性提升 17%。

与 K3 的异同：用于评测而不是训练；图谱是从给定数据里抽出来的，不是 agent 联网扩出来的。

13KNIGHT

  • 机构 / 时间：德黑兰大学等；arXiv 2026-02-23
  • 链接：arXiv 2602.20135；GitHub 1⭐

做法：给定主题和深度，检索证据，建一个主题小 KG（类型体系基于 Wikipedia/Wikidata 本体），在 KG 上生成多跳选择题。KG 每个主题只建一次，之后反复使用，比每题重新读长证据省 token。

怎么验题：五条标准，包括语法、唯一正确答案、选项不重复、能从证据中答出、切题；「答不出」被当作幻觉的代理指标。难度用熵和人类错误模式校准。

14SkillSynth（腾讯混元）

  • 全称：Toward Scalable Terminal Task Synthesis via Skill Graphs
  • 机构 / 时间：腾讯混元团队；arXiv 2026-04-28
  • 链接：arXiv 2604.25727

图谱怎么建：从 ClawHub 和公开 GitHub 仓库收集真实技能；为每个技能推出「前置场景」（什么时候能用）和「后置场景」（用完处于什么状态）；把语义兼容的场景连起来。场景是节点，技能是有向边。现有规模：去重合并后 82,073 个场景、57,214 个技能、185,529 条经 LLM 验证的连接。

怎么采样和出题：从图上采一条有向路径，就是一个真实工作流；多 agent 把路径实例化成可执行的终端任务，预期解法正好走这条路径。

怎么验题：oracle 验证可解，rubric 评质量，失败的回到合成环节修复。

效果：一次全自动运行，从 3,721 条路径得到 3,560 个通过验证的任务，oracle 通过率 95.7%，平均每个 $27.3；Terminal-Bench 1.0 和 2.0 上各尺寸模型都有提升；已用于训练 Hy3 Preview。

与 K3 的异同：K3 控制的是「知识覆盖」，SkillSynth 控制的是「解题轨迹的多样性」。原文还批评 LLM 生成的 taxonomy 常常偏离真实使用，所以它的节点全部来自真实技能。

15ToolVerse（美团 LongCat）

  • 机构 / 时间：美团 LongCat Interaction Team、北大、复旦、武大；arXiv 2026-07-17
  • 链接：arXiv 2607.15660

做法：从约 422 个真实 MCP 环境、4,438 个工具自动生成可执行环境（约 20% 初始工具集因无法 mock 被过滤）；对每个场景建工具依赖图，从入度为 0 的根节点出发，用「动态解锁采样」逐步解锁后继工具，组合出长程任务，得到 GUST 数据集。

D 自动建树

17ATLAS

  • 全称：Agentic Taxonomy of LArge-Scale Software Ecosystems
  • 机构 / 时间：中科院软件所、南洋理工、南开等；ASE 2026，arXiv 2026-06
  • 链接：arXiv 2606.21597

做法：Designer agent 结合模型知识和真实仓库样本，提出每个节点的「切分维度」；Classifier agent 把仓库分进去；分不进去的失败案例反过来驱动修改维度。按广度优先逐节点构建，每个节点只需带祖先链的维度信息，而不是整棵树，所以成本随树的大小而不是语料大小增长。最后做层级对齐，保证不同分支的粒度一致。

效果：54,387 个 GitHub 仓库；在 2,001 个仓库的分层样本上 TQF 83.13%，比最强基线高 15 个点；用于找替代软件 P@1 85.71%，高于人工整理列表的 62.34%。

与 K3 的异同：只建树不造题，但它补上了 K3 没写的部分：怎么判断一棵 agent 长出来的树好不好、怎么让各分支粒度一致。「每个节点只带祖先链」和 K3「检索词拼祖先上下文」是同一个思路。

类比

20和植物识别数据全集

植物识别的做法：先用物种分类（界门纲目科属种）定义「全集」，再在每个叶子上找图片，按类目补齐数量，长尾物种单独补采。对照下来：

植物识别 K3 / 本页的工作
物种分类树（现成，生物学定好） 概念图谱（K3、SearchArt 由 agent 长出来）或能力 taxonomy（CLI-Universe 人定）
叶子是「种」 叶子是「足够原子的概念」（K3）、技能（SkillSynth）、实体（SearchArt）
按物种搜图，搜索词带上科属避免同名 关键词拼祖先上下文检索（K3）；只带祖先链做决策（ATLAS）
每类保证最少样本数，长尾单独补 按领域配额采样并动态调整（SearchArt、BenchBench）；专挑模型见得少的长尾实体（SearchArt）
图片人工审核、去重 可执行校验、fail-to-pass、多模型评审组（CLI-Universe、SkillSynth、BenchBench）
分类本身有争议时要修树 分类失败反过来修维度（ATLAS）

两点不同：

  1. 物种树是现成的、公认的；LLM 训练的知识树没有标准答案，所以 K3、SearchArt、ATLAS 都让 agent 边查边长树，树本身也成了产出。
  2. 植物数据是「一个叶子对应一堆样本」；造题经常要「多个节点组合」（K3 的 RoPE + GPU kernel、STEPS 的技能组合、工具图上的路径），组合怎么挑是新的问题。

面试

21可以讲的观点

  1. 覆盖率要靠结构管，不能靠模型自由发挥。 让模型自由出题会集中在它熟悉的热门知识上。SearchArt 原文直说图采样会偏向稠密区域，所以要用 taxonomy 和动态配额拉平；SkillSynth 则批评 LLM 生成的 taxonomy 偏离真实使用，改从真实技能建图。面试可以讲：覆盖地图从哪来（人定、模型推、agent 联网长、真实日志），各有什么偏差。
  2. 「采样 → 真实素材 → 出题」的关键在中间一步。 K3 和 CLI-Universe 都要求先拿到真实网页、仓库、issue，再出题。这一步决定题目是否有据可查、是否有真实的坑，也是数据公司能和模型公司自产数据拉开差距的地方。
  3. 验证成本才是大头。 CLI-Universe 淘汰约三分之二候选；SkillSynth 每个合格任务约 $27.3、通过率 95.7%；FireFly 用「先观察结果再倒推题目」让答案构造即正确。谈数据生产线时，应该先讲淘汰率和单题成本，再讲产量。
  4. 图的节点类型决定能练什么能力。 概念节点练知识覆盖（K3），实体节点练多跳搜索（SearchArt、DeepDive），工具或技能节点练执行轨迹（SkillSynth、ToolVerse）。设计评测时先问清楚：要测的是知识面、搜索深度，还是工作流执行。
  5. 评测集本身也可以这样生成和体检。 BenchBench 发现出题能力和答题能力只中等相关（ρ≈0.37），无效题会拉低区分度（r≈−0.62）；Graph2Eval 用可达性分析保证可解。做评测岗可以讲：自动生成的评测集要报告无效率和区分度，而不只是模型分数。
