1. 预训练数据

模型 原文要点
DeepSeek-V3 “we train DeepSeek-V3 on 14.8T high-quality and diverse tokens”
DeepSeek-V4 在 V3 数据基础上过滤 “batched auto-generated and templated content”，以降低模型坍缩风险；“incorporating agentic data during the mid-training phase”；重点加长文档（论文、技术报告）；总量 “more than 32T tokens”
Qwen3 36T、119 种语言；用 Qwen2.5-VL 从 PDF 抽取文本，用 Qwen2.5-Math / Coder 合成数据；三阶段：约 30T 通用 → STEM 和代码 → 长上下文
Kimi K2 15.5T。针对知识和数学数据做改写（rephrasing），用分块自回归重写长文档并校验语义一致；论文用 SimpleQA 对比了“改写”和“多轮重复”，改写更好
GLM-4.5 / 5 4.5 是 23T，含仓库级代码拼接（学跨文件依赖）；5 是 “a massive 27 trillion token corpus, prioritizing code and reasoning early on”，之后的 mid-training 聚焦 “long-context agentic data”，总计 28.5T
MiniMax-M1 / M2 M1 在 Text-01 上用 7.5T 推理密集语料继续训练；M2 预训练 29.2T，上下文 192K
Seed-OSS 12T；同时发布带合成指令数据和不带的两版 base，原因是合成指令数据“may affect the post-training research”

2. SFT 与合成数据

模型 原文要点
DeepSeek-V3 “instruction-tuning datasets to include 1.5M instances spanning multiple domains”；推理数据由专家模型生成
DeepSeek-R1 冷启动只用 “thousands of cold-start data”；随后拒绝采样得到约 600k 推理数据（只保留正确的），加约 200k 非推理数据，合计 800k，也用这批数据蒸馏小模型
DeepSeek-V3.2 / V4 每个领域先训一个专家模型（推理、agentic coding、agentic search 等），再蒸馏进统一模型；V4 把这一步“entirely replaced by On-Policy Distillation”
Qwen3 冷启动用过滤后的长 CoT；思考模式融合阶段把带推理和不带推理的数据合并训练
GLM-4.5 先训推理、Agent、通用对话三个专家模型，再用自蒸馏合并
Kimi K2.5 发现加入人工设计的视觉轨迹会损害泛化，改用纯文本 SFT（zero-vision SFT）再做联合 RL

3. RL 环境与奖励

模型 环境 奖励
DeepSeek-R1 数学、代码、逻辑 accuracy reward + format reward；推理任务不用神经网络 RM，原因是 “neural reward models are susceptible to reward hacking”
Qwen3 推理 RL 的 query-verifier 对要满足：冷启动没用过、模型能学会、足够难、覆盖面广，共 3,995 对 通用 RL “covering over 20 distinct tasks, each with customized scoring criteria”：规则、带参考答案的模型打分、不带参考答案的模型打分
Kimi K2 真实和合成工具环境，加上执行沙箱 RLVR + self-critique：模型对照 “core rubrics”“prescriptive rubrics” 和人工标注的 rubric 自评
GLM-4.5 搜索：知识图谱多跳合成，加上人工从网页抽取并“selective obfuscation”；SWE：GitHub PR/issue 加可执行单元测试，在加固沙箱中运行 搜索用最终答案正确性；SWE 用测试；工具调用格式错误给过程惩罚；按难度做课程学习，因为全对或全错的 batch 没有梯度
GLM-5 “over 10,000 verifiable training scenarios”（SWE 和终端），加可扩展的多步搜索合成 异步 RL（slime），生成和训练解耦
MiniMax-M1 41 类逻辑推理任务（SynLogic），加基于 SWE-bench 的沙箱 可验证任务用规则；问答、写作等不可验证任务用生成式 RM
MiniMax-M2 SWE-Scaling 流水线：爬 PR → agent 构建多语言 Docker 环境 → 按 PR 类型分流 → 抽取 F2P / P2P 测试 → 模型校验 → 增强 “artifact-aligned reward”：奖励与交付物格式对齐，不用通用 judge
LongCat-Flash-Thinking-2601 “over 10,000 environments spanning more than 20 domains” 论文的重点在环境扩展和噪声鲁棒性

4. Agent 轨迹数据

模型 原文要点
Kimi K2 三步：生成工具规格（3,000+ 真实 MCP 工具，演化出 20,000+ 合成工具）→ 生成 agent 和任务，任务配 rubric（“specifies success criteria, expected tool-use patterns, and evaluation checkpoints”）→ 多轮轨迹由 LLM 模拟用户（“LLM-generated user personas”）生成，再由 LLM judge 按 rubric 过滤
DeepSeek-V3.2 RL 任务表：code agent 24,667（真实环境、抽取的 prompt）、search agent 50,275（真实环境、合成 prompt）、general agent 4,417（环境和 prompt 都是合成的）、code interpreter 5,908；论文另有 RL 只用合成 general agent 数据的实验
MiniMax-M2 Agentic Cowork 有四个领域：深度搜索、知识工作者办公、金融表格、幻灯片。办公类“anchor the corpus to GDPval”，再按职业数据库层级合成任务，配真实 workspace 和不同具体程度的 query；验收用“multi-axis rubric covering positive behaviors, negative behaviors, critical errors, regional appropriateness, and depth of reasoning”；搜索题用“guide-and-rewrite”逐步隐去实体来调难度，要求答案有实际检索证据支撑；轨迹从轮换的 teacher 模型蒸馏，并扰动 scaffold
GLM-4.5 搜索 QA 结合自动合成（知识图谱多跳）和人工混淆；SWE 轨迹来自真实 PR

对数据公司和评测 PM 意味着什么

  1. 采购重心在可验证环境：GLM-5（10K+）、LongCat（10,000+ 环境）、V3.2（1,800+ 环境）都在比环境数量。能直接交付 Docker 环境、测试和 verifier 的供应商（智能知识的 Terminal/MCP 数据、Copula 的 RL 环境）站在需求最大的地方。
  2. 不可验证任务靠 rubric：Kimi K2 的 self-critique rubric、MiniMax M2 的多轴 rubric 验收、Qwen3 的 20 多类自定义打分标准，说明专家写的 rubric 本身就是产品，和 OMB、XpertBench 的评测方法是同一套能力。
  3. GDPval 已成为 office 类任务的起点：MiniMax 直接拿 GDPval 做种子再扩展。Copula 的中文 GDPval 和金融长程题正好补中文和本地合规这块空白。
  4. SWE 数据已经工业化：PR → Docker → F2P/P2P 测试，几家做法高度一致，差异化要靠多语言、非 bug-fix 类任务（feature、性能、迁移），对应 RoadmapBench、SWE Refactor Bench 这类评测。
  5. 防 reward hacking 是共识：R1 不用神经网络 RM 的理由、M2 要求答案有检索证据支撑、EdgeBench 和 EvoCode 的泄题案例都指向这一点。评测 PM 的价值在于设计 judge 隔离、隐藏测试和审计流程。
  6. 公开信息的缺口：字节 Seed 和 Qwen3.5 没有公开数据细节；各家都不报告 judge 和人工的一致率。面试时可以作为切入点。
